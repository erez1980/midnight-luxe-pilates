# הפעלת תיקוני האתר והאפליקציה

## לפני פריסה

1. לקחת גיבוי לטבלת `shared_lessons` ולנתוני המשתמשים ב־Supabase.
2. להריץ `supabase/migrations/20261009_secure_sharing.sql` ב־SQL Editor של הפרויקט הנכון. הסקריפט אינו מוחק שיעורים. הוא מחליף את הרשאות השיתוף, מוסיף בעלות/תוקף ו־RPC לשליפה של שיעור בודד.
3. לבדוק בעזרת anon key רגיל שקריאה ישירה של כל טבלת השיתופים חסומה, וקישור ידוע עדיין ניתן לקריאה דרך `get_shared_lesson`. לבדוק שלקישור שאינו קיים/פג תוקף מתקבל null.
4. ליצור שיתוף בחשבון A, לבדוק שחשבון B אינו יכול לקרוא את רשומות השיתוף של A ישירות או לבטל אותן, ולבדוק שבעל הקישור מצליח לבטל אותו.
5. לוודא ש־Google OAuth חוזר ל־`https://erez1980.github.io/midnight-luxe-pilates/app/` ושהכתובת נמצאת ב־Redirect URLs ב־Supabase.
6. לאחר הצלחת CI והפעלת ה-migration, למזג את PR הקוד ל־main. ה־workflow בונה ופורס אוטומטית ל־GitHub Pages. PR לבדו אינו פורס.

## מה משתנה בנתונים

- מפתחות האחסון המקומי החדשים מופרדים לפי user ID. נתונים ישנים לא משויכים לחשבון אוטומטית; בסביבת העבודה מופיע כפתור להעברה מודעת כעותקים.
- טיוטות חדשות מופרדות לפי משתמש ושיעור. הטיוטה משוחזרת לפני כתיבה חדשה; כישלון קריאה אינו גורם לדריסתה.
- סנכרון שולח כל שינוי בנפרד עם בדיקת `updated_at`. הוא אינו מוחק את כל מה שחסר במכשיר. מחיקת שיעור משאירה tombstone ב־payload כדי שמכשיר אחר לא ישחזר אותו בטעות.
- בהתנגשות משתמש בוחר במפורש איזו גרסה לשמור, ויכול להוריד גיבוי לפני הבחירה. כתיבות רצות בתור אחד.
- קישורים חדשים משתמשים ב־token אקראי של 192 ביט, תקפים ל־30 יום וניתנים לביטול בידי בעליהם. ביטול אינו מוחק עותקים שכבר נשמרו אצל נמענים.
- לקישורים ישנים אין בעלות אמינה שניתן להסיק. ה-migration משאיר אותם תקפים ל־30 יום ממועד הריצה; ביטול פרטני דורש מנהל אחרי אימות הבקשה.
- קישורי base64 ישנים ממשיכים להיפתח אחרי בדיקת נתונים. קישור שמכיל את השיעור עצמו אינו ניתן לביטול. שיתוף כזה אינו fallback אוטומטי לשגיאת ענן.
- Service worker חדש מרענן לקוחות קיימים כדי לטעון את קוד הסנכרון החדש. כדאי לסגור/לרענן לשוניות ישנות בכל המכשירים לאחר הפריסה.

## בדיקות

`npm audit` דיווח על אפס חולשות לאחר עדכון התלויות. `npm test` מריץ 13 בדיקות לוגיקה. `npm run typecheck` מריץ TypeScript במצב strict. `npm run test:e2e` בודק ממשק עם חשבון ובסיס נתונים מדומים; הוא אינו פונה לפרויקט Supabase האמיתי. `npm run build` אורז את שני עמודי האתר.

לבדיקה מקומית עם Chromium מותקן: `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e`. אחרת: `npx playwright install chromium` לפני הבדיקה.

אימות אמיתי לאחר פריסה: התחברות עם Google, שני חשבונות באותו דפדפן, שני מכשירים עם אותו חשבון, עריכה/מחיקה בזמן ניתוק רשת, שיתוף וביטול שיתוף. הפעלת ה-migration ובדיקות מול בסיס הנתונים האמיתי לא בוצעו באמצעות סביבת עבודה זו.
